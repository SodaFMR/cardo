# Cardo P6 — Look, Motion and Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every pixel of Cardo: the design system, the procedural cardo (thistle) flower with its seven motion states, the bottom-sheet assistant panel with result cards, onboarding, home, settings, reminders, notes and about screens. Bilingual, accessible and smooth, with state-driven composables that P7 wires to the real engine.

**Architecture:** Jetpack Compose in `:app` under `io.github.sodafmr.cardo.ui`. Every screen is a stateless composable taking a UI-state data class and callbacks; preview/test fakes drive them. The flower is one Canvas composable with precomputed geometry and an animation controller, reused in the panel, home and onboarding. Visual regressions are caught by Roborazzi screenshot tests on the JVM (Robolectric), so no emulator is needed for this plan.

**Tech Stack:** Compose BOM 2026.09.00 (Material 3, animation, foundation), Navigation Compose (with shared element transitions), AndroidX DataStore Preferences, Core SplashScreen, Robolectric + Roborazzi (newest release compatible with the toolchain), Compose UI test.

**Spec:** `docs/superpowers/specs/2026-11-01-cardo-v1-design.md` (section 8; section 4 "Listening policy" and section 2 for settings values)

## Global Constraints

- Colours (exact):

  | Token | Hex |
  |---|---|
  | Thistle Violet | `#7B4BD1` |
  | Bloom Magenta | `#C24BC9` |
  | Lilac | `#B9A2F0` |
  | Bract Sage | `#8FA89A` |
  | Night | `#0E0B14` |
  | Petal White | `#F6F2FB` |

  The panel is always dark; app screens follow system light/dark.
- Type: Figtree (SIL OFL 1.1), bundled. Transcript 28 sp, reply 20 sp.
- Panel:
  - Gradient scrim from transparent at ~55% screen height to Night at 92% opacity at the bottom edge, unless `blurBehind` is true (then a lighter tint).
  - The flower is centred at the bottom edge and grows out of it.
  - Keyboard button bottom-left, close button bottom-right.
  - Cards spring up between the text and the flower.
- Flower anatomy: a bulbous base of overlapping spiky bracts (Bract Sage); a crown of 60–90 curved filaments in a Thistle Violet → Bloom Magenta gradient with Lilac/Petal White tips; a soft radial glow behind.
- Flower motion (exact values):

  | State | Motion |
  |---|---|
  | Appear | Bud rises from below the edge on a spring (dampingRatio 0.72, stiffness 380). Bracts unfold over 250 ms, then filaments bloom staggered over 450 ms. |
  | Listening | Filament length follows the level with 60 ms attack / 150 ms release, up to +35%, with per-filament noise phases, plus ±3° idle sway. |
  | Thinking | A hue wave travels around the crown at ~1.2 rev/s and the glow breathes. |
  | Speaking | Glow and filament pulse follow the output level. |
  | Success | A short brightening, then 6–12 thistle-down seeds float up and fade over 900 ms. |
  | Error | Colour drops by 30% and the filaments droop for 400 ms. |
  | Dismiss | Filaments retract over 220 ms and the bud sinks on a spring. |
- Performance: no allocation inside `DrawScope` lambdas (paths, brushes and arrays are created in `remember`), draw under 4 ms, 120 Hz ready.
- Reduced motion (animator duration scale 0, or the system "remove animations" setting): crossfades and a static flower only.
- Motion is spring-first; no linear tweens on interactive elements.
- Every user-visible string is in `res/values/strings.xml` and `res/values-es/strings.xml`. TalkBack labels on every icon button; text contrast ≥ 4.5:1 (≥ 3:1 for 24 sp+).
- Settings values (exact):
  - Listening mode: `ALWAYS` (default), `SCREEN_ON_OR_CHARGING`, `CHARGING_ONLY`, `OFF`.
  - Sensitivity: `LOW`, `NORMAL` (default), `HIGH`.
  - Language: `AUTO` (default) with a primary language EN/ES.
  - Voice feedback: `AUTOMATIC` (default), `ALWAYS`, `NEVER`.
  - Pause below 10% battery: on.
  - Sounds and haptics: on.
  - History: off.
  - Lock-screen rules per feature group: calls, messages, calendar, reminders and notes, apps — each `ALLOW`/`CONFIRM`/`UNLOCK`. Defaults: calls ALLOW, messages UNLOCK, calendar UNLOCK, reminders and notes ALLOW, apps UNLOCK.
- Do not depend on `:voice`. Depend on `:brain` only for `Response`, `Card`, `UiAction`, `Choice`, `ReminderItem`, `EventItem`, `Lang` and other schema types. P7 wires everything else.
- Commits: plain messages, no `Co-Authored-By` / "Generated with" trailers. While iterating run `./gradlew :app:testDebugUnitTest --tests '<class>'`. Record screenshots with `./gradlew :app:recordRoborazziDebug` and verify with `verifyRoborazziDebug`.
- For craft, implementers may consult the `impeccable` skill (native Android screens) when shaping layouts and copy. Task 9 runs an `impeccable` audit pass.

## Review Focus

1. Very long content — a 40-word transcript, a 300-character message preview, 12 calendar events, a German-length Spanish string — must wrap, scroll or truncate gracefully without pushing the flower or buttons off-screen.
2. Font scale 200% and display size "largest" must keep every screen usable (no clipped buttons, the panel still dismissible).
3. Rapid state changes (Listening → Thinking → Result inside 150 ms, or Dismiss arriving mid-Appear) must not snap, flicker or leave the flower half-drawn.
4. Light and dark system themes on app screens; the panel stays dark in both.
5. Reduced-motion mode must still communicate state (static flower tint per state plus text), not a frozen bloom.

### Task 2: The flower

**Files:**
- Create under `app/src/main/kotlin/.../ui/flower/`: `FlowerGeometry.kt`, `FlowerAnimator.kt`, `CardoFlower.kt`, `ThistleSeeds.kt`
- Test: `ui/flower/FlowerGeometryTest.kt`, `ui/flower/FlowerScreenshotTest.kt`, `ui/flower/FlowerAnimatorTest.kt`

**Interfaces:**
- Produces:
  - `enum class FlowerState { Hidden, Appear, Listening, Thinking, Speaking, Success, Error, Dismiss }`
  - `class FlowerGeometry(seed: Int = 7, filamentCount: Int = 72, bractRows: Int = 4)`: precomputed unit-space filament angles, lengths, curvature, tip colours and bract polygons. Deterministic per seed.
  - `@Stable class FlowerAnimator(reducedMotion: Boolean)` exposing animated scalars read in draw: `rise`, `bractOpen`, `bloom[i]`, `amplitude`, `hueShift`, `glow`, `droop`, `desaturate`, `seedsProgress`. `suspend fun animateTo(state: FlowerState)` cancels the in-flight transition and continues from current values (Review Focus 3). `fun setLevel(level: Float)` applies attack/release smoothing.
  - `@Composable fun CardoFlower(state: FlowerState, level: () -> Float, modifier: Modifier = Modifier, frameOverride: FlowerFrame? = null)`
  - `data class FlowerFrame(val state: FlowerState, val progress: Float, val level: Float)`: renders a fixed frame for screenshots/tests.
  - Appear/Success/Dismiss transitions complete on their own: `Appear` settles into `Listening`'s idle look; `Success` returns to a resting bloom; `Dismiss` ends fully below the edge.
- Drawing:
  - Bracts: layered pointed shapes with sage gradient and subtle highlight.
  - Filaments: cubic curves from the bulb top with violet→magenta gradient and lighter tips; per-filament width 1.2–2.4 dp.
  - Glow: radial gradient behind.
  - Seeds: tiny pappus particles (a dot plus 6–8 fine radial hairs) drifting upward with sideways sway.
  - All `Path`/`Brush` objects are reused through `remember` caches keyed on size.

  - `FlowerAnimatorTest` (virtual clock): `animateTo(Appear)` reaches `rise == 1f` and `bloom.all { it == 1f }` by 700 ms; a `Dismiss` interrupting at 150 ms ends at `rise == 0f` with no value jumps > 0.2 between frames; a level step of 1.0 lifts `amplitude` to ≥ 0.6 within 60 ms and decays more slowly; with `reducedMotion` there's no sway and seeds are skipped
  - screenshots: each `FlowerState` at progress 0.5 and 1.0 (`frameOverride`), dark background, 240 dp box
